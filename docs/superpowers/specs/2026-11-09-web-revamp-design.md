# Naarad web revamp: dithered backgrounds and product visuals

Date: 2026-11-09 · Status: draft for review · Scope: whole site

## Goal

Give the whole static site a premium, on-brand look: dithered backgrounds, a
product-visual treatment for the route tracker, and the intro video as hero
content. Brand kit v1.0 is the reference.

## What the user supplied, and what that means

| Item | Reality | Plan |
|---|---|---|
| Dither | Open source (`dither-dither`, `dithering-shader`) | Write our own ~80-line vanilla WebGL module. No dependency. |
| Ultramock | Hosted app, no repo | User exports device mockups (stills and video) from `route_tracker_alpha.mov`. We embed the exports. |
| Animos | Hosted app, no repo | User exports a motion reel. We embed it. |
| Background Supply | Hosted app, no repo | User exports backgrounds. They are optional; dither is the default. |
| "interfaces" | Unidentified | Out of scope until the user names it. |
| Intro video (`.mp4`, 7 MB) | Not yet viewed | Compress, add a poster, embed in the home hero. |
| Route tracker (`.mov`, 140 MB) | Not yet viewed | Source for Ultramock only. Never committed raw. |

## Constraints (from the repo)

- Static HTML on GitHub Pages. Pages are generated by `scripts/build-site.mjs`
  from `app/shell.html`. Edit the shell and the data, not the 41 output pages.
- Tokens live in `app/base.css` `:root`. `app/visual-contract.md` governs the
  look and contrast. Text pairs must keep their documented ratios (WCAG AA).
- `sw.js` caches files by `VERSION` (now `v44`). Any new asset means a bump.
  `scripts/check-sw-cache.mjs` enforces this.
- `scripts/verify.sh` is the gate. It must stay green.
- No new runtime dependency and no framework.

## Design

### 1. Brand tokens
Map the brand kit onto the existing tokens instead of adding a second set:
Deep Navy #0B1D3A → `--ink-deep`, Forest Green #1E5B46 → new `--forest`,
Heritage Orange #F26A1C → `--orange-bright`, Sand #F2E8DB → `--paper-deep`.
The current `--ink`, `--orange` and `--paper` values stay where contrast needs
them. Orange text on sand fails AA, so the existing darker `--orange-text`
remains the text colour. #F26A1C is for fills and dithers only.

### 2. Dither module (`app/dither.js`)
- One exported `mountDither(el, {back, front, scale, speed})`.
- Renders a Bayer-matrix ordered dither of an animated noise gradient into a
  `<canvas>` absolutely positioned behind the element's content.
- Mounted on any element with `data-dither`. Default pair: navy back, orange
  front at low contrast. Sand/forest variants via `data-dither="sand"`.
- Fallbacks: no WebGL → static CSS gradient with the same colours.
  `prefers-reduced-motion` → one still frame, no animation loop.
- Pauses when off-screen (IntersectionObserver) and when the tab is hidden.
- Never sits under body text without an overlay that keeps text contrast ≥ 4.5:1.
- Test: a small assert-based check that the Bayer threshold function returns
  only the two colours and that the fallback path is taken when `getContext`
  returns null.

### 3. Where it is used
- Home hero (behind the intro video poster).
- Page-header band on Explore, Routes, Stories, Collections, Creators, About.
- Footer band.
Route and story reading pages stay on plain paper so long text stays readable.

### 4. Intro video
Home hero gets a `<video>` with `poster`, `preload="metadata"`, controls, no
autoplay with sound. Compressed H.264 mp4 (target ≤ 3 MB, 1280 wide) plus a
WebP poster. Video files are excluded from the service worker precache.

### 5. Route tracker visual
A "How it works" section on the home page uses the Ultramock export (a still
for first paint, the video on demand). If no export exists yet, the section is
omitted rather than shown empty.

### 6. Fonts (decision for the user)
The brand kit asks for Cinzel and Inter; the site ships Playfair Display and
DM Sans. Default in this spec: **keep the current fonts** for this revamp, since
swapping touches every page's metrics and the 41 generated pages. Switching to
Cinzel + Inter is a separate, small follow-up if wanted.

### 7. Out of scope
Rebuilding on a framework, new features, the "interfaces" tool, editing the
user's source videos, anything that sends data to a third party.

## Build order
1. Tokens + `app/dither.js` + tests, mounted on the home hero only.
2. Page-header and footer bands across the site via `shell.html`.
3. Video embed and route-tracker section once the assets exist.
4. Rebuild pages, bump `sw.js` `VERSION`, run `scripts/verify.sh`.

## Risks
- Video and mockup assets depend on the user's exports; steps 1–2 do not.
- `ffmpeg` is not installed here; step 3 needs `brew install ffmpeg`.
- Animated canvases cost battery on low-end phones; mitigated by pause rules
  and the reduced-motion fallback.
